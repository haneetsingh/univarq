# Univarq — Final Copy

Humanized pass over `univarq-copy-review-v2.md`, run through the actual `/humanize-writing` skill. Directional changes from v2 are preserved: no "consultancy" framing, architecture is one capability among several and not the lead differentiator, throughline is one team, every layer, start to finish.

This version supersedes the first draft of this file — the first pass was done before the skill was available and missed a few things the skill's checklist catches directly (an Oxford comma, a couple of leftover em dashes, and a "not X" construction repeated four times across the page). Those are fixed below and in the site components.

A later pass also removed every use of a colon as a list separator ("problems from first sketch to production: frontend, backend..."), which reads as a template even without an Oxford comma attached, and caught one more Oxford comma this pass had missed in the About section's own list. Those are folded into sections 1, 2 and 4 below.

---

## 1. Hero Section

> We build the software your business actually runs on.
>
> Univarq takes ownership of technology problems from first sketch to production, whether that's frontend, backend, cloud, data or AI. We understand what you're trying to do, take it on as our own and we deliver it.

*Corrections: the closing clause had an Oxford comma before "and we deliver it" — "understand... take it on... and we deliver it" is a three-item series, so the comma before "and" needed to go. Separately, the opening sentence used a colon to introduce the list ("...to production: frontend, backend..."), which is the exact stock construction the skill flags — rewritten as "whether that's X, Y or Z" instead, which reads as a person talking rather than a formatted spec sheet.*

## 2. About Univarq

> Straight answers, not a committee.
>
> Univarq takes on hard technology problems and owns them. We don't hand you a recommendation and leave the building. We've shipped systems at scale before and this isn't our first time doing it under pressure.
>
> The same team that understands the problem builds the solution, end to end, across frontend, backend, cloud infrastructure, data platforms and AI. Nobody gets handed off to a different specialist for every layer.
>
> Some engagements, we sit inside your team and build alongside them. Others, we own the whole initiative ourselves. Either way you're talking to the person doing the work, today, not an account manager relaying an update from someone who is.

*Changes from previous pass: dropped the em dash in paragraph 1 and split it into two short sentences instead ("We don't hand you a recommendation and leave the building.") so the negative framing lands as its own beat rather than being welded to the sentence after it. Removed the Oxford comma from "embedded in your team, running our own initiative, or somewhere in between" by cutting the phrase and restructuring — see paragraph 3. Paragraph 3's closing line now has a concrete detail ("today") instead of a flat claim, and doesn't repeat the exact "not X" shape used in the other two paragraphs.*

*Later correction: paragraph 2 used a colon to open the list ("Frontend, backend, cloud infrastructure, data platforms, AI: the same team...") — same template pattern as the Hero fix above. Rewritten so the list sits inside a normal sentence ("across frontend, backend, cloud infrastructure, data platforms and AI") instead of being front-loaded and colon-separated. That also fixed a latent Oxford-comma risk: the old version listed five items with no "and" before the last one, which read like a spec sheet; the new version closes properly with "data platforms and AI," no comma before "and."*

*Further correction: dropped the comma in paragraph 1's closing sentence ("...at scale before, and this isn't our first time...") on request — it's grammatically a comma joining two independent clauses rather than a true Oxford comma, but the shorter unbroken sentence reads tighter, so it stayed cut. Left the equivalent commas in paragraph 3 ("Some engagements, we sit... Others, we own...") untouched per direction — those set off an introductory phrase rather than joining two full clauses, and read differently out loud.*

## 4. Why Univarq

> Why teams call Univarq

*Changes from previous pass: removed the em dash and the Oxford comma from entry 1 ("frontend, backend, cloud, data, AI, it's one team" is gone) and rewrote it as one clean sentence with "and" before the last item, no comma. Entry 2's second sentence changed from "not a strategy deck someone else has to implement" to "Someone else can write the deck" — same idea, but it drops the fourth instance of the "not X" pattern that was repeating across every single entry on this page (About had two, this page had two more).
